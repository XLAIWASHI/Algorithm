## 前言
在正式开始排序算法前，我们需要先了解一些设计思想

假设现在有一个排序算法的开发者，他希望自己的算法能够被不同的用户使用：

- 不同的用户需要排序的类型不同
- 使用的类型不光有基本类型和标准库类型，还有用户自定义的类型
- 即使是同样的类型，用户的比较规则也可能不同

那么问题是：

> **如何设计一个排序算法，使她不需要关心具体的数据类型，也不需要提前知道用户的排序规则，却依然可以满足不同用户的需求** 

为了解决这个问题，我们需要引入两个重要思想：

1.**泛型思想(Template)** 
- 解决类型变化的问题，使同一份算法能够处理不同类型的数据
- 可以处理不同类型的数据

2.**回调机制(Callback)** 
- 解决不同排序规则的问题
- 允许用户将自己的比较规则传递给算法，由算法在需要比较时主动调用该规则

## 泛型思想
假设，我们需要交换两个变量
```cpp
void swap(int& a, int& b)
{
    int temp = a;
    a = b;
    b = temp;
}
```
这个函数只能交换 `int` 
如果需要其他类型，只能重写；导致写很多代码
但是，用泛型就可以解决这个问题

```cpp
template<typename T>
void swap(T& a, T& b)
{
    T temp = a;
    a = b;
    b = temp;
}
```
这里的 `T` 只是一个占位符
使用时
```cpp
int a, b;
swap(a, b);
```
编译器会 **根据调用时提供的类型，对模板进行实例化，生成对应版本的函数** 

**注：**
如果是函数的话，编译器可以根据参数类型，推导出需要的类型；这个过程叫作： **模板参数推导** 
如果是类模板的话，就不可以，比如
```cpp
template<typename T>
class ResizingArrayQueue
{
private:
    T* array;
    int size;
};
```
声明
```cpp
ResizingArrayQueue queue;
```
编译器不知道当前需要的是什么类型
所以
```cpp
ResizingArrayQueue<int> q;
```
类模板的话需要给定一个类型

**总结** 
> **在排序算法中，泛型让算法不依赖具体的数据类型**

## 回调机制
虽然泛型解决了不同类型变化的问题，但是还有一个问题：

**不同用户对于同一种数据类型，可能有不同的排序需求** 

---
例如，有一个学生类
```cpp
class Student
{
public:
    string name;
    int age;
    double score;
};
```

对于 `Student` 类型的数据，不同的用户可能希望按照不同规则排序：

- 按名字排序
- 按年龄排序
- 按成绩排序

甚至可能存在更加复杂的排序规则：

- 年龄相同时，比较成绩
- 成绩相同时，比较名字

---
因此，我们无法提前在排序算法内部定义一个固定的比较方式

排序算法只应该负责：

- 遍历数据
- 调整元素位置

而 “如何比较” 这个问题，应该交给用户决定

这个时候，我们就需要 **回调机制(Callback)** 

> **回调机制就是将一个函数传递给另一个函数，在需要的时候由接收方主动调用该函数** 
---
### Callback的实例
```cpp
#include <iostream>

void execute(int a, int b, void (*func)(int, int))
{
    func(a, b);
}

void add(int a, int b)
{
    std::cout << a + b << std::endl;
}

void multiply(int a, int b)
{
    std::cout << a * b << std::endl;
}

int main(void)
{
    execute(3, 5, add);
    execute(3, 5, multiply);
	
    return 0;
}
```
输出：
```
8
15
```
将 `add` 和 `multiply` 的 **函数地址** 作为参数传递给 `execute` 由 `execute` 在需要执行操作时主动调用对应的函数
这里 `execute` 并不知道具体执行的是加法还是乘法，
它只负责在需要的时候调用传入的函数
